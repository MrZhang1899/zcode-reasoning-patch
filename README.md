# ZCode 思考等级补丁包

## 日常使用

保持 `run-patch.cmd`、`patcher.cjs`、`discover.ps1` 和 `restart.ps1` 在同一目录。`test.cjs` 和 `restart.test.ps1` 是可选测试文件，日常运行不需要。双击 `run-patch.cmd` 打开中文菜单，不会自动安装：

```text
1. 看看补丁装好了没
2. 先备份一下
3. 开始打补丁
4. 用备份恢复
5. 换一个 ZCode 安装位置
6. 重启 ZCode
0. 退出
```

先确认菜单上显示的是你要修改的 ZCode；位置不对就选 5。选 1 只检查，不改 ZCode 文件。选 2 保存当前文件，已有补丁也会一起保存。选 3 会先检查、备份，再打补丁，不会自动重启。

选 4 是回到备份保存时的内容，不等于卸载补丁：备份里有全部或部分补丁，恢复后也会保留。列表会说明备份时间、备份时机、是否含补丁，以及能否用于当前版本；不能恢复时会显示原因。

文件修改后，ZCode 下次加载这个文件时才会读取修改。重启成功只确认新窗口已启动，不证明服务端支持所选思考等级。

选 6 可单独重启当前选择的 ZCode。先保存全部工作，再输入大写 `YES` 确认；当前会话会中断，其他输入或输入结束都会取消。请在 ZCode 外单独打开 CMD 运行工具，或双击启动工具；从这个 ZCode 里打开的工具不能用来重启它自身。

工具只会正常关闭当前选择的 ZCode，不会强制结束，也不会自动重试。请处理保存提示；关闭最多等待 20 秒，启动新窗口最多等待 15 秒，整个重启助手最多运行 45 秒。失败时有些窗口可能已经关闭，新窗口也可能稍后才出现，请自行检查。只支持安装目录内有 `resources/glm/zcode.cjs` 和 `ZCode.exe` 的 ZCode，不提供 `--restart` 命令行参数。

工具会记住所选安装位置。上次选择仍能找到时会优先使用；找不到时提示重新选择。找到多个安装时由你选择，未找到时可输入安装目录或 `zcode.cjs` 完整路径。用于运行工具的 ZCode.exe 不一定就是你要修改的那个安装。

## 重启与查找安装的技术说明

重启助手按可执行文件完整路径匹配进程，不按名称批量关闭。仅在本机检查进程命令行中的 `--type` 以排除 Electron 子进程，不输出或保存命令行。排除工具解释器 PID 和祖先进程；若所选 ZCode 是工具的祖先进程，拒绝操作，请从外部 CMD 或双击启动本工具。正常关闭窗口后最多等待 20 秒，确认所选安装的应用进程退出才发出一次 GUI 启动请求；未运行时仅启动一次。无主窗口、信息不可验证、关闭被拒绝或超时均停止，不强制终止、不自动重试。请及时处理应用的保存提示；失败时部分窗口可能已经正常关闭。整个助手调用有 45 秒上限。启动后最多等待 15 秒，要求精确所选 exe 路径、非工具/祖先 PID、非旧 PID、非 renderer 的新进程，且同一 PID 的主窗口连续两次可见，才报告启动确认。超时保留待重启状态，不重试、不强制结束；应用可能稍后才启动。GUI 确认仍不代表运行时请求或服务端思考等级已经验证。

祖先检查要求调用者 PID 在进程快照中唯一存在。父 PID 已退出（快照不存在），或其 CreationDate 晚于子进程（PID 已复用）时，结束该段存活祖先遍历；缺失创建时间不能作为跳过祖先的依据。仍拒绝精确所选路径的存活 ZCode 祖先、循环及无法读取路径的祖先；仅允许 PID 4、名称 System、父 PID 0 的无路径系统根进程。调用者和助手自身仍被排除。

只读诊断可从 PowerShell 执行以下命令，`$PID` 必须来自仍存活的调用 PowerShell，不要使用过期 PID、猜测 PID 或 CMD 的进程变量：

```powershell
& .\restart.ps1 -Executable 'D:\ZCode\ZCode.exe' -ToolProcessId $PID -ValidateOnly
```

`validated-only` 仅说明本次祖先检查通过，不验证窗口、关闭或启动能力；失败时输出中文原因。此开关不访问窗口、不关闭、不等待、不启动、不修改设置，也不输出命令行。没有新增 CLI 重启参数。

GUI 启动前仅在助手的子环境中清除 `ELECTRON_RUN_AS_NODE`、`ELECTRON_NO_ATTACH_CONSOLE`、`ELECTRON_NO_ASAR`、`NODE_OPTIONS` 和 `NODE_PATH`，不修改系统环境或调用者环境。

启动器切换到 UTF-8 代码页，优先使用 PATH 中的 Node.js（建议当前 LTS），否则通过共享的 `discover.ps1` 查找 ZCode Electron，以 `ELECTRON_RUN_AS_NODE=1` 执行脚本，不打开应用界面。找不到运行时可手动输入 ZCode.exe 路径。已有 Node 不兼容时安全报错，不切换运行时重试。

发现范围包括 D:\ZCode、LocalAppData 下的 Programs\ZCode 和 ZCode、Program Files，以及 HKCU/HKLM 的普通和 WOW6432Node 卸载项、App Paths\ZCode.exe；另通过只读 Win32_Process 查询正在运行的 ZCode.exe 路径。不扫描整盘，不读取进程命令行或用户配置。注册表或进程信息因权限不可读时跳过，仍检查其他来源。

有效目标选择会记忆在本包 `settings.json`。只有记忆路径仍存在且位于有效发现结果中才优先使用；否则警告并回退。找到多个安装且无有效记忆时，交互菜单要求选择；非交互命令拒绝猜测，必须传入 `--target`。菜单 5 忽略记忆偏好，仍可更换目标。没有找到目标时菜单允许输入安装目录或运行时文件路径。运行时启动所选的 Electron 仅用作 JS 解释器，不代表自动选中了修改目标。

## 命令行

以下命令在本包目录的 CMD 中执行。安装目录和 `resources\glm\zcode.cjs` 文件路径均可用作目标；原有位置参数路径、`--check`、`--no-pause` 保留。不指定操作时进入菜单，包括只传路径的情况。

```bat
run-patch.cmd --check --no-pause
run-patch.cmd --check --target "D:\ZCode" --no-pause
run-patch.cmd --check --no-pause "D:\ZCode\resources\glm\zcode.cjs"
run-patch.cmd --backup --target "D:\ZCode" --no-pause
run-patch.cmd --apply --target "D:\ZCode" --no-pause
run-patch.cmd --list-backups --target "D:\ZCode" --no-pause
run-patch.cmd --restore "D:\ZCode\resources\glm\zcode.cjs.reasoning-时间戳-随机值.bak" --yes --target "D:\ZCode" --no-pause
```

自动化必须明确指定操作。`--restore` 必须加 `--yes`；交互恢复先列出可恢复备份，再选择编号并输入 `YES`。`--no-pause` 或 `ZCODE_PATCH_NO_PAUSE=1` 禁用 CMD 退出前等待，不代替恢复确认。成功退出码为 0，命令失败为 1；菜单内错误显示后可继续选择。输入结束会退出菜单。

`--check` 检查六处对应代码、修改后的文件能否正常读取，以及原文件有没有被其他程序改动，不修改安装目录，也不创建备份；检查用的系统临时文件会清理。六处补丁已全部安装时，`--apply` 也不会重复写入或备份。每处补丁显示编号和状态，写入时显示检查阶段、数量和备份位置。

## 六处精确补丁

1. `mN`：缺省 options 提供 openaiCompatible 和 openai；OpenAI 设置 forceReasoning，off 转 none。
2. `h2e`：等级映射提供两个 provider，OpenAI 设置 forceReasoning。
3. GPT `JS` 等级：low、medium、high、xhigh、max。
4. Chat Completions reasoningEffort 枚举增加 max。
5. `LSo`：保留 DeepSeek 已有内容，增加 OpenAI reasoningEffort 和 forceReasoning。
6. `sNi`：OpenAI off 对应 none 和 forceReasoning，其他 provider 分支不变。

六处修改前和修改后的精确签名不变。所有签名必须唯一，缺失、重复、函数改名或未知压缩布局均拒绝整次安装，不会部分应用。不是通用跨版本补丁；更新覆盖后只有签名仍完全符合才能再次应用。未通过付费 API 验证服务端是否接受各等级。

## 备份与恢复保护

备份在目标旁排他创建 `.reasoning-时间戳-随机值.bak` 和同名 `.bak.json`，不覆盖已有文件。元数据只记录目标路径、时间、版本清单及哈希、原始/当前 SHA-256、全部六处补丁规范化后的完整源码 SHA-256；不读取或保存用户配置、接口地址或凭据。

即使工具不认识当前代码，也可以单独备份，但这类备份无法通过恢复检查，不能自动恢复。列表会显示所有符合本工具命名格式的备份，包括不能用于当前版本、缺少配套校验记录的旧备份，并说明原因。

列表用中文显示备份时机（手动备份、打补丁前、恢复前或未知）、备份内容（未装补丁、装了部分补丁、已装全部补丁或无法判断），以及“可以恢复”或“这份备份不能用于当前版本”。内部记录仍保留原有的 `manual` / `preapply` / `prerestore`、`unpatched` / `partial` / `full` / `unknown` 等值。补丁状态根据备份文件实际内容判断，恢复前会重新执行全部检查。历史 `.reasoning-effort.bak` 也会显示为不可恢复，不会自动删除。

恢复不等于卸载补丁。想回到未装补丁的状态，必须选择同一版本、检查通过且显示“未装补丁”的备份；选择含全部或部分补丁的备份，恢复后仍会保留对应补丁。

恢复仅接受目标同目录、本工具命名格式、带有效元数据的普通备份文件；拒绝符号链接、外部任意路径、错误目标、版本变化、备份内容变化和无关源码修改。检测 `resources/app/package.json` 和运行时同目录 package.json（存在时）的版本和完整文件哈希；无版本清单时，以全部补丁规范化后的完整源码哈希作为可靠构建身份。即使版本号相同，任何六处补丁之外的代码变化也会拒绝恢复。允许同一构建的未补丁、部分补丁和全部补丁状态互相恢复，不允许旧备份覆盖新版源码。

元数据不是数字签名，无法抵御有本地写权限的人同时恶意伪造备份和元数据；不要使用他人提供的备份。

恢复先验证备份和当前目标，再对同目录候选做语法检查，保存恢复前的当前文件，复核目标及版本后原子重命名，并验证结果。原备份和恢复前备份都保留。重复恢复到相同内容时不写入。安装也在语法检查、备份校验及并发复核后同目录原子替换；失败不退回截断写入，不自动恢复。

除菜单 6 经明确确认的重启外，工具不停止、重载或重启任何现有进程，不联网。请等待应用更新结束再操作：哈希检查能发现已发生的并发变化，但无法锁住第三方更新程序，最后复核与重命名之间仍存在极短竞争窗口。权限、文件锁或重命名失败会安全报错。修改在应用下一次加载运行时时生效。

## 状态与本地日志

实际 apply 或 restore 替换目标后，本包 `settings.json` 按目标记录 `pendingRestart: true`，明确提示文件已写入、需要手动重启。检查、重复应用、相同内容恢复、取消或失败重启均不清除此状态。只有菜单 6 明确确认且助手验证新 GUI 成功才清除；不会根据外部手动重启猜测验证成功，所以手动重启后此标记可能继续保留。没有标记也不证明当前进程已经加载补丁，文件已安装更不是服务端接受各等级的证据。

`settings.json` 自动生成，仅包含格式版本、所选目标路径和各目标待重启标记，不保存凭据。缺失、损坏、不可读会提示并回退；目录不可写时警告，本次仍可操作但状态不能跨次保存。不要把删除设置当作已验证重启。

每次运行在本包 `logs/` 生成时间戳和随机后缀日志，记录操作开始/结束、检查阶段、备份路径及错误；检查失败时报告应用版本（没有版本记录时显示“未知”）、文件校验值 SHA-256、所有失败的精确补丁标签及匹配计数。六处全有或全无签名校验失败不写目标、备份或候选文件，本包日志/设置不受此只读承诺限制。

日志只记录工具自己的诊断，不捕获用户输入、完整环境或进程命令行，不读取用户配置、密钥或接口地址。常见凭据格式和 URL 脱敏后同步写入并 fsync，每条关闭文件，不依赖退出时缓冲刷新。日志目录不可写则警告并退回终端，不改变安全保护。`settings.json`、`logs/` 是生成的本地文件；历史日志和备份都不会自动删除。
