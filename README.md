# ZCode Reasoning Patch

**给 Windows 版 ZCode 补齐部分思考等级设置的传递逻辑。**

一个非官方的本地补丁工具，提供中文菜单，支持检查、备份、打补丁、恢复和重启。发布版只需下载一个 `.cmd` 文件，无需手动配置脚本。

> [!WARNING]
> 本工具会修改 ZCode 的本地运行文件，请先保存工作，并等 ZCode 更新完成后再操作。
> 已针对 **ZCode 3.11.2.6792** 的代码制作补丁，不保证兼容其他版本。新版代码不匹配时，工具会停止安装。

## 能做什么

- **检查补丁状态**：逐项显示六处补丁是否已经安装。
- **自动找安装位置**：检查常见目录、注册表和正在运行的 ZCode，也可以手动选择。
- **先备份再修改**：打补丁前自动备份，也支持单独备份。
- **用备份恢复**：显示备份时间、是否含补丁、能否用于当前版本。
- **按需重启**：只有主动选择并确认，才尝试正常关闭并重新打开 ZCode。
- **记住选择、保留日志**：保存上次选择的安装位置，出错后可以查看记录。

## 下载与使用

### 单文件版（推荐）

1. 打开本仓库的 **Releases** 页面，下载附件 `ZCode-Reasoning-Patch.cmd`，不是 GitHub 自动生成的源码压缩包。
2. 双击运行，确认界面上的 ZCode 安装位置正确。
3. 先选 **1** 检查，再选 **3** 打补丁。
4. 修改完成后自行重启 ZCode，或保存工作后选择 **6**。

工具不会联网下载依赖。优先使用电脑上的 Node.js；没有 Node.js 时，会尝试使用已安装 ZCode 自带的运行环境。

> [!NOTE]
> “单文件”指只需分享和下载一个文件。运行时会自动解包，并在 `%LOCALAPPDATA%\ZCode-Reasoning-Patch` 保存必要文件、设置和日志。

### 源码版

下载源码，将下面四个文件放在同一文件夹，然后双击 `run-patch.cmd`：

```text
run-patch.cmd
patcher.cjs
discover.ps1
restart.ps1
```

源码版的设置和日志保存在工具所在文件夹。测试文件不是日常运行的必需文件。

## 菜单说明

| 选项 | 用途 |
| --- | --- |
| 1. 看看补丁装好了没 | 只检查，不修改 ZCode 文件。 |
| 2. 先备份一下 | 保存当前文件，包括已经装上的补丁。 |
| 3. 开始打补丁 | 检查代码、自动备份，再写入修改；不会自动重启。 |
| 4. 用备份恢复 | 回到所选备份保存时的状态，恢复前也会备份当前文件。 |
| 5. 换一个 ZCode 安装位置 | 选择要操作的安装目录，不是更换模型或供应商。 |
| 6. 重启 ZCode | 保存工作后输入 `YES` 确认，只重启当前选中的安装。 |
| 0. 退出 | 关闭工具。 |

进入功能时会清屏。结果和错误会保留，按 Enter 后再返回菜单。

## 补丁范围与限制

补丁主要补齐 OpenAI 相关请求路径中的思考等级映射，包括 Responses 和 Chat Completions 的部分处理：

- 保留 GPT 的五个选项：`low`、`medium`、`high`、`xhigh`、`max`。
- 为部分等级映射补齐 `openai` 和 `openaiCompatible` 两套参数。
- 补齐 DeepSeek 的 Responses 等级映射，以及关闭选项对应的 `none`。
- 保留原有的 Anthropic 等专用映射，不修改供应商地址、密钥或模型配置。

> [!IMPORTANT]
> **补丁安装成功，不等于供应商支持这些等级，也不等于实际请求已经验证成功。**
> 这不是所有模型的通用修复，更不会给不支持思考功能的模型增加该能力。服务端是否接受 `max`、`none` 等值，仍取决于具体供应商。

六处代码必须都符合工具认识的格式，才会安装；缺失、重复或结构发生变化时，整次操作会停止，不会只装一半。已经装好的补丁不会重复写入。

## 备份与恢复

备份保存在 **ZCode 运行文件旁边**，由 `.bak` 文件和配套的 `.bak.json` 校验记录组成。需要保留恢复能力时，请一起保留它们。

- **恢复不等于卸载补丁。** 备份里有补丁，恢复后仍然有补丁。
- 想回到未打补丁的状态，需要选择同一版本、检查通过且显示“未装补丁”的备份。
- 旧版本备份不能覆盖更新后的 ZCode；文件被改动、校验记录缺失等情况也会被拒绝。
- 不使用他人提供的备份。工具的校验记录不是数字签名，不能防止有人同时伪造备份和记录。

## 常见问题

### 更新 ZCode 后还能用吗？

更新可能覆盖补丁。更新完成后重新运行工具检查；只有相关代码仍然匹配，才能重新安装。如果提示不支持，请保留错误信息，等待补丁适配，不要拿旧版运行文件覆盖新版。

### 为什么手动重启后，还显示需要重启？

工具只会在通过菜单成功重启后清除这个标记，不会猜测你是否在外部重启过。这个提示可能继续保留；同样，没有提示也不能证明供应商已经收到思考等级。

### 重启失败怎么办？

从桌面双击工具，或从 ZCode 外部的 CMD 打开。先保存工作，再选择重启。如果有保存提示，请先处理；工具不会强制结束进程，也不会自动重试。超时后应用仍可能稍后启动，请先查看实际窗口，避免重复操作。

### 哪些文件可以删除？

源码版的 `test.cjs`、`restart.test.ps1` 和 `README.md` 不影响日常运行。历史 `logs/` 可以清理；删除 `settings.json` 会丢失安装位置和待重启记录。单文件版不需要附带源码文件夹。

### 提交问题时需要提供什么？

请提供 Windows 和 ZCode 版本、选择的菜单项、完整错误提示，以及是否使用单文件版。日志包含本机文件路径，**分享前请检查并遮盖用户名等个人信息**；不要上传密钥、ZCode 用户配置或完整的 ZCode 运行文件。

## 进阶说明

<details>
<summary><strong>命令行用法</strong></summary>

以下为源码版命令。在工具目录的 CMD 中执行；单文件版将 `run-patch.cmd` 换成 `ZCode-Reasoning-Patch.cmd`。示例中的 `D:\ZCode` 请换成实际安装目录。

```bat
run-patch.cmd --check --target "D:\ZCode" --no-pause
run-patch.cmd --backup --target "D:\ZCode" --no-pause
run-patch.cmd --apply --target "D:\ZCode" --no-pause
run-patch.cmd --list-backups --target "D:\ZCode" --no-pause
run-patch.cmd --restore "完整备份路径.bak" --yes --target "D:\ZCode" --no-pause
```

不指定操作时进入菜单。目标可以是安装目录或 `resources\glm\zcode.cjs` 文件路径。`--restore` 必须加 `--yes`；`--no-pause` 只取消退出前的等待，不代替确认。

命令成功退出码为 `0`，失败为 `1`。没有非交互重启参数，重启只能通过菜单确认。

</details>

<details>
<summary><strong>六处修改的技术说明</strong></summary>

| 位置 | 修改内容 |
| --- | --- |
| `mN` | 缺省推理配置补齐两个 provider namespace；`off` 转为 `none`。 |
| `h2e` | 等级映射补齐 `openai` 参数及 `forceReasoning`。 |
| GPT `JS` 列表 | 使用 `low / medium / high / xhigh / max` 五档。 |
| Chat Completions 参数校验 | `reasoningEffort` 枚举增加 `max`。 |
| `LSo` | DeepSeek 映射增加 OpenAI 参数，保留已有内容。 |
| `sNi` | OpenAI 关闭选项映射为 `none`，保留其他 provider 分支。 |

这些名称来自已适配版本的压缩代码，不是稳定接口。`forceReasoning` 用于打开 SDK 的参数序列化路径，不保证远端支持该参数；与 `none` 配合时，不表示要求启用思考。

</details>

<details>
<summary><strong>文件安全、本地数据与重启规则</strong></summary>

- 写入前检查所有代码特征及候选语法、保存备份、复核文件哈希，再以同目录替换方式安装。
- 恢复同时检查目标路径、版本信息、备份哈希和完整规范化源码指纹，不允许旧备份覆盖新版代码。
- 检查不能锁住第三方更新程序，最后复核与替换之间仍有极短竞争窗口。请不要在 ZCode 更新过程中使用工具。
- `settings.json` 记录安装位置和待重启状态；`logs/` 记录操作步骤、备份路径和错误。工具不读取供应商配置或密钥，不记录完整进程命令行。设置与日志写入失败时会提示。
- `--check` 不修改 ZCode 安装目录，但可能生成工具自己的设置、日志及会被清理的临时检查文件。
- 重启按完整可执行文件路径匹配，不按名称批量关闭。工具从所选 ZCode 内部启动时拒绝重启它自身。
- 父进程已退出或 PID 已复用时，正确结束对应的父进程检查；无法确认的其他情况仍保守拒绝。
- 正常关闭最多等待 20 秒，新窗口确认最多等待 15 秒，助手总调用上限为 45 秒。失败不强制结束，也不自动重试。
- 新进程和主窗口通过检查后才报告重启成功，但这仍不等于请求参数或服务端效果已验证。

源码版可以进行只读的启动来源检查，不会关闭或启动窗口：

```powershell
& .\restart.ps1 -Executable 'D:\ZCode\ZCode.exe' -ToolProcessId $PID -ValidateOnly
```

这里的 `$PID` 必须来自仍在运行的调用 PowerShell。`validated-only` 只表示本次启动来源检查通过。

</details>
